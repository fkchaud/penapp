# Waiter Role (`waiter`)

Order-taking flow for the waiter role: build a new comanda against a table, and browse/edit the orders assigned to the selected waiter.

## Overview

| File | Role |
| --- | --- |
| `take_order.tsx` | Route component for composing and placing a new order. |
| `orders/` | Nested order list and edit routes. |

Both routes depend on a waiter selected on the home screen and persisted in `WaiterContext` (AsyncStorage key `waiter_obj`). Composed components come from `penapp/components/OrderTaking/*`; HTTP adapters come from `penapp/hooks/useApi`.

Parent: [app](../README.md)

## Interface

### Routes

- `/waiter/take_order` — `take_order.tsx`.
- `/waiter/orders` — `orders/index.tsx`.
- `/waiter/orders/[id]/edit` — `orders/[id]/edit.tsx`.
- Drawer entries `waiter/take_order` ("Tomar pedido") and `waiter/orders/index` ("Ver pedidos") are shown only when `userType == UserType.Waiter && waiter`; the edit route is hidden (`display: "none"`). See [app](../README.md).

### Module exports (`take_order.tsx`)

- `default TakeOrder` — wrapper holding the remount key (`useState<string>`, reset to `Math.random().toString()` on focus).
- `InternalTakeOrder` — not exported. Props: `{ reset: () => void }`.

### React Query keys (`take_order.tsx`)

- `["foods"]` → `getFoods`; `enabled: isFocused`; `refetchOnWindowFocus: true`.
- `["drinks"]` → `getDrinks`; `enabled: isFocused`; `refetchOnWindowFocus: true`.
- Mutation is local (`useMutation`), not keyed.

### API calls (`take_order.tsx`)

- `GET /api/foods/`, `GET /api/drinks/`.
- `POST /api/place_order/` (`placeOrder(order, { "Idempotency-Key": idemKey.current || "" })`) returning `{ orderId: number }`.

### Contexts (`take_order.tsx`)

- `UserTypeContext` → `userType` in the payload.
- `WaiterContext` → `waiter` (guard + `waiter.name`).
- `AlertContext` → `setAlertMessage`, `setOnDismiss`.

### Components (`take_order.tsx`)

`ConfirmOrderModal`, `TableTopBar`, `FoodPicker`, `ConfirmBottomBar`.

### Order payload (`OrderToPlace`)

`waiter: waiter.name`, `table: currentTable?.number`, `food: [{ id, quantity }]`, `drinks: [{ id, quantity }]`, `payment_type: paymentMethod`, `comment`, `user_type: userType`.

## Invariants

- Remount contract: the route renders `InternalTakeOrder key={key}` and resets the key on every `useIsFocused()` change, so form state and the idempotency key are discarded on blur/focus.
- Redirect guard: while focused, a 100 ms timeout calls `router.replace("/")` if `waiter` is still falsy; the timeout is cleared on blur/unmount. The delay exists to let `WaiterContext` finish reading `waiter_obj` from AsyncStorage.
- `buildOrder()` throws `Error("Empty payment method")` when `paymentMethod` is `""`, and `Error("No waiter selected")` when `waiter` is falsy. It is invoked synchronously by the modal's `onConfirm`, before `mutate`.
- Payment method is chosen inside `ConfirmOrderModal`; it starts as `""` on every mount.
- "Continuar" is enabled only when `totalPrice > 0 && !!currentTable`; `totalPrice` is the sum of `price × quantity` over both maps and is recomputed by an effect.
- The idempotency key is regenerated by `useEffect` on `[isFocused, currentTable, totalPrice, comment]` (and created on mount by `useIdemKey`); any table or basket change therefore yields a new `Idempotency-Key` for the next `place_order` call.
- Quantity `0` removes an item from its map; positive quantities overwrite the entry.
- `FoodPicker` receives `Object.values()` of the catalog maps; before the queries resolve the arrays are empty and no `ActivityIndicator` is rendered on this route.
- `TableTopBar` is used with defaults (`autoCurrentTable: true`), so the first fetched table at/above `waiter.from_table` (or the first table) becomes `currentTable`; the list is limited to the waiter's table range unless "Mostrar todas las mesas" is toggled.
- "Limpiar" (`ConfirmBottomBar.onCancel`) calls `reset`, remounting the inner component and clearing table, basket, comment and payment method.

## Side Effects

- HTTP: `GET /api/foods/`, `GET /api/drinks/` on focus; `POST /api/place_order/` with the `Idempotency-Key` header on confirm.
- Cache: `invalidateQueries(["foods"])` and `invalidateQueries(["drinks"])` on focus change, on unmount, after success and after error.
- Storage: none directly (waiter persistence is owned by `_layout.tsx`).
- Navigation: on success the Snackbar's `onDismiss` performs `router.navigate("/waiter/orders")`; the guard uses `router.replace("/")`.
- UI feedback: Snackbar `"Comanda enviada: #<orderId>"` on success, `"Error: <message>"` on failure (also `console.error`); the modal confirm button shows `isPending` loading state.
- Cache of orders (`["orders"]`, `["order", id]`) is not invalidated here; the order list refreshes on focus and by polling.
